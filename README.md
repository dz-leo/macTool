# Mac 工具管理台

一个跑在你自己 Mac 上的本地工作台：管理 brew 服务、一键直达配置与目录、磁盘缓存清理、快捷键速查、命令片段库，外加每天一条的 Mac 小技巧。

**零第三方依赖**：bridge 只用 Python 标准库，页面是单文件 HTML（无 CDN、无字体外链、无构建步骤）。不装任何软件，不申请任何系统权限。

---

## 环境要求

- macOS 12 及以上（在 macOS 15.6 上开发实测）
- Python 3.9+（macOS 自带 `/usr/bin/python3` 即可，无需安装任何包）

## 安装与启动

### 方式一：双击启动（推荐）

把整个 `macTool` 文件放在任意位置（如 `~/Sites/macTool`），然后双击：

```
启动工作台.command
```

它是「智能启动」：服务已在后台运行 → 直接打开工作台；没在运行 → 自动拉起后台服务再打开页面。日常使用**不需要保持终端窗口开着**。

> 如果双击提示"无法打开"，右键 → 打开（macOS 对网络脚本的一次性确认）。

### 方式二：手动启动（临时调试用）

```bash
cd ~/Sites/macTool        # 换成你的实际路径
python3 mactool-bridge.py # 默认端口 8899，被占用会自动顺延
```

这种方式关掉终端 = 停止服务，只适合临时调试。

### 方式三：后台常驻 + 开机自启（推荐长期使用）

bridge 由 macOS 的 launchd 托管后：**登录自动启动、进程崩溃自动拉起、跟终端窗口完全无关**，平时感觉不到它的存在。

安装（在项目根目录执行，只需一次）：

```bash
sed "s|__INSTALL_DIR__|$PWD|" com.mactool.bridge.plist.template \
  > ~/Library/LaunchAgents/com.mactool.bridge.plist
launchctl load -w ~/Library/LaunchAgents/com.mactool.bridge.plist
```

> launchd 不展开 `~` 和环境变量，配置里必须是写死的绝对路径，所以用模板先替换成本机实际路径再加载。
> plist 放入 `~/Library/LaunchAgents` 后，即使不执行 `load`，**下次登录也会自动生效**。

日常操作：

| 想做什么 | 命令 |
|---|---|
| 立即启动（本次登录内） | `launchctl load -w ~/Library/LaunchAgents/com.mactool.bridge.plist` |
| 停止本次运行（下次登录仍自启） | `launchctl unload ~/Library/LaunchAgents/com.mactool.bridge.plist` |
| 彻底卸载自启 | `launchctl unload -w ~/Library/LaunchAgents/com.mactool.bridge.plist && rm ~/Library/LaunchAgents/com.mactool.bridge.plist` |
| 查看运行状态 | `launchctl list | grep mactool` |

自启日志在 `/tmp/mactool-bridge.log` 和 `/tmp/mactool-bridge.err`。

> **「页面上能不能一键启动 bridge」**：做不到——页面是跑在浏览器里的，bridge 不在时页面本身就没有执行通道，这是先有鸡还是先有蛋。所以方案是让 launchd 提前把 bridge 常驻后台，你永远不需要手动启动。

## 功能说明

### 1. 服务控制台
- 列出所有 brew 服务：运行状态、监听端口、配置文件路径
- 一键启动 / 停止 / 重启（`brew services` 走用户域，全程不需要 sudo）
- 端口占用速查：谁在监听哪个端口，可一键结束进程（仅限当前处于监听状态的进程）
- 「需要注意」置顶区：服务停止、端口异常、可更新包、磁盘紧张都会主动提醒

### 2. 一键直达
- 内置本机常用配置（nginx / redis / mysql / php.ini / zshrc …）与常用目录
- 每条支持：**编辑器打开** · **Finder 显示** · **在此处打开终端** · **直接新建文件**
- 「在指定目录新建文件」就是网页版右键新建：选目录、填文件名、创建后可选择立即编辑
- 可添加自定义快捷方式

### 3. 磁盘清理
- 只扫描**白名单内的缓存类目录**，个人文档、照片、桌面文件一律不碰
- 三个档位自主选择：
  - **保守**：废纸篓、.DS_Store —— 确定安全
  - **标准**：用户应用缓存（`~/Library/Caches`）、日志、npm / Yarn 缓存
  - **深度**：再含 Xcode 编译产物、模拟器缓存、Gradle 缓存等开发缓存（下次编译会重建）
- 「iOS 设备备份」默认归入深度档并单独标红警示——可能包含微信聊天记录，没有备份别勾它
- 扫描只读；清理前弹出完整清单二次确认，删除不可恢复
- 清理只删目录内容、保留目录本身；嵌套目录（如 Homebrew 缓存属于用户缓存子目录）自动去重
- 被占用的文件会跳过并如实报告，不会强杀进程

### 4. 快捷键速查
内置 70+ 条常用快捷键（系统 / 窗口 / 文本编辑 / Finder / 截图 / 终端 / 编辑器），支持搜索与收藏，收藏存本地。

### 5. 命令片段库
brew / 服务 / 端口 / 文件 / git 常用命令，一键复制，可添加自己的片段。

### 6. 每日小技巧
- 每天一条 Mac 技巧（30+ 条轮换），可手动「换一条」
- 「不装软件 · 原生就能做到」专区：窗口分屏、Spotlight 启动器、活动监视器监控、菜单栏整理等原生替代方案
- 含 **Automator 自制「右键新建文件」分步教程**（附可复制脚本），零安装实现 Finder 右键新建

## 安全说明

bridge 的安全边界（写死在代码里，请勿放宽）：

| 边界 | 说明 |
|---|---|
| 只监听回环地址 | `127.0.0.1`，局域网和外网都访问不到 |
| 仅白名单动作 | 没有「执行任意命令」接口；服务名、PID、动作全部白名单校验 |
| 路径越权校验 | 拒绝 `..` 穿越、相对路径；新建文件只允许创建单个常规文件 |
| 清理目标硬编码 | 清理接口只接受预定义的 key，客户端永远传不进路径 |
| 结束进程受限 | 只能结束当前处于监听状态的进程，且拒绝 PID 1 与自身 |

页面数据（收藏、自定义快捷方式与片段）全部存在浏览器 localStorage，不上传任何服务器。设置菜单里可导出 JSON 备份 / 导入恢复。

**提醒**：把页面部署到线上后的链接是「只读版」——浏览器不允许线上页面访问你本机的 127.0.0.1，动态功能自动隐藏，只保留快捷键 / 命令 / 技巧等知识内容。

## FAQ

**Q：打开页面显示「离线模式」？**
A：bridge 没在跑。双击 `启动工作台.command` 即可；装了方式三的 LaunchAgent 后，这种情况基本不会再出现（登录即启动、崩溃自动拉起）。注意要用 bridge 的地址（`http://127.0.0.1:8899`）访问，不要直接双击 HTML 文件（那样只有静态内容）。

**Q：点「启动服务」报错？**
A：个别服务的 launchd 注册可能被系统安全策略拦截，直接在终端跑 `brew services start 服务名` 看具体报错。bridge 只是转发这条命令。

**Q：清理扫描很慢？**
A：扫描用 `du` 实际统计目录大小，缓存目录大时要等几秒到几十秒，属正常。

**Q：清理时有条目删不掉？**
A：文件正被应用占用。关掉对应应用再清，或者忽略——bridge 会如实报告跳过了什么，不会强删。

**Q：端口 8899 被占了？**
A：bridge 自动顺延到 8900+。终端里打印的地址以实际为准。

**Q：换浏览器 / 清了浏览器数据，我的收藏没了？**
A：收藏存 localStorage。定期在「设置与数据」里导出 JSON 备份。

## 开发约定

改代码前先读这一节，避免破坏既有架构。

**统一风格**：编码 UTF-8 ／ 换行 LF ／ 末尾留一空行 ／ 不保留行尾空格 ／ 缩进用空格（Python 4 格，其余 2 格）。规则写在 `.editorconfig` 里，编辑器会自动遵守。

**`mactool-workspace.html` 的分层是硬约束**：

```
数据层（loadData / saveData）
   ↓
计算层（compute* / filtered*）
   ↓
渲染层（render*）
```

调用链单向向下，**渲染函数之间严禁互调**；任何视图刷新统一走 `refreshAll()`。网络请求只允许改 `state` 再统一刷新，不要在请求回调里直接操作 DOM。

**`mactool-bridge.py` 的安全边界不许放宽**：只监听回环地址、仅白名单动作、清理目标硬编码、路径做越权校验。新增接口时按同样标准来。
